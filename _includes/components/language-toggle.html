{% comment %} Feature: ZER0-078 {% endcomment %} {%- comment -%} Component: language-toggle Path: _includes/components/language-toggle.html Purpose: Switches between the English original and its machine-generated translations (scripts/translate.rb). Shows the source language plus every configured target language. Every entry is a live link: a target without a generated translation for the current page falls back to the source page and is explained by one footnote (it used to render as a disabled entry — see T-038). Params: variant (string, optional, default "navbar") - "navbar" — compact dropdown for the header utility cluster - "panel" — self-contained "Language" section for the Settings offcanvas (components/info-section.html), rendered as an always-visible list of choices with its own
heading Reads: page.lang / page.url / page.translation_source_url and the generated _data/i18n/manifest.yml. Depends on: site.translation.* config, site.data.i18n.manifest, _data/i18n/languages.yml (display names), core/i18n.html, Bootstrap 5 dropdown (navbar variant only), Bootstrap Icons (bi-translate) Notes: Renders nothing when translation is disabled or no target languages are configured. The chosen language is remembered in localStorage("zer0-lang") for future UX (no auto-redirect). Must NOT be include_cached — the menu is page-dependent. The theme ships the "panel" variant (the navbar is reserved for main navigation); "navbar" stays for consumers that prefer the header dropdown. MENU CONTRACT (T-038 / #406) — shared by both variants: * No DISABLED rows. A target language without a generated translation is still a link; it goes to the source-language page and still records the preference in zer0-lang, so the menu never contains a dead end. * The current language is marked with a check icon and a subtle tint — NOT Bootstrap's `.active` primary fill, which read as a selected nav item rather than "you are here". * Machine-generated translations carry a small "auto" chip. The source language never does (a human wrote it), and neither do untranslated rows (nothing was generated). * The per-row "(Not yet translated)" text is replaced by ONE footnote under a divider, referenced from each untranslated row via aria-describedby. Per-row text was the single biggest contributor to menu width. Trigger changes (icon-only, no caret) apply to the navbar variant only — the panel has an
heading, not a button. New ui keys (lang_machine_translated, lang_machine_translated_title, lang_untranslated_note) live in _data/ui-text.yml `en`. core/i18n.html REPLACES the whole `ui` map on a translated page rather than merging it, so until scripts/translate.rb regenerates _data/i18n/.yml these keys are absent there — every use below therefore carries a literal `| default:` fallback.
