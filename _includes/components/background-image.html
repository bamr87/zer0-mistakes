{% comment %} Feature: ZER0-004 {% endcomment %} {% comment %} BACKGROUND IMAGE - Cover art painted as a CSS background, announced correctly Sibling to components/preview-image.html. Reach for THIS one when the art is painted as a CSS background on an otherwise empty box; reach for preview-image.html when the art is an in the content flow. WHY THIS EXISTS. A CSS background is invisible to assistive technology. A box painted with cover art and nothing else announces nothing at all, so the reader is told there is an element and never told what it shows. The fix is role="img" plus an aria-label, which makes the box a single graphic with a name. The theme already did this by hand in three places (components/abc-letter.html, layouts/article.html rating stars, components/theme-customizer.html) without it being a named convention. TWO BRANCHES, and the second is not optional: real image -> role="img" aria-label="..." (a graphic with a name) decorative -> aria-hidden="true", and NO role and NO aria-label Combining aria-hidden with role="img" is worse than either alone: it announces a graphic and then hides it. A gradient placeholder carries no information the surrounding text does not already carry, so it is hidden. Usage: {%- include components/background-image.html src=post.preview alt=post.title class="card-cover" style="height: 180px;" -%} {%- comment -%} decorative fallback: omit alt, or pass decorative=true {%- endcomment -%} {%- include components/background-image.html class="card-cover card-cover-empty" -%} Params: src - image path (optional; omit for the decorative branch) alt - accessible name; REQUIRED for the real-image branch class - CSS classes on the box (default: "bg-cover") style - extra inline style, appended after the background shorthand decorative - force the decorative branch even when src is present tag - element name (default: div) Path convention is preview-image.html's, duplicated rather than extracted: it is ~14 lines of Liquid, and a third shared include to save them buys less than it costs in indirection. preview-image.html remains the source of the convention -- change it there first. - /images/previews/x.png -> /assets/images/previews/x.png - /assets/images/previews/x.png -> unchanged - https://example.com/x.png -> unchanged (external URL) DO NOT apply this to a box that wraps text. role="img" makes the element a single graphic and its descendants stop being exposed -- so putting it on _includes/content/intro.html, which paints a background AND wraps the page
