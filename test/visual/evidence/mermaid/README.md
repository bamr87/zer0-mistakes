Two things worth reading off that table:

- **The toggle bug is a total loss, not a glitch.** Before, one colour-mode switch leaves `hasSvg = false` for the rest of the page's life — the "back to light" and "skin" rows never recover. After, every row has its SVG and the palette follows the mode and skin.
- **The palette really is the theme's.** The after border colour equals `--bs-primary` in both skins (`#6fa8dc` air, `#8338ec` neon); no colour is hard-coded in the component.

## A second bug this surfaced

While chasing grey pie slices, the culprit turned out to be `assets/js/obsidian-wiki-links.js`: it rewrites `#hashtag`-shaped tokens in text nodes and skips `STYLE` ancestors by `nodeName` — but SVG-namespace elements report `style` in lower case, so it walked into every rendered diagram's `<style>` and turned its `#id` selectors into tag links, unscoping the rules for the whole page. Fixed in the same PR (case-insensitive check, `<svg>` subtrees skipped, `.zer0-diagram` exempt), with a fixture in `test/test_resolver.js` and a pie-fill assertion in the spec.
